# 粮满满

农资本地配送平台（"农资界的美团"）：农户打开小程序看到附近的农资店和店里的货，下单后老板送货上门，也可以到店自提或快递发货。

```
liangmanman/
├── backend/    Java 17 + Spring Boot 3 + MyBatis-Plus + MySQL 8（后端，含定时任务）
├── miniapp/    uni-app (Vue 3)：微信小程序（买家端 + 商家端），同一套代码可编译 iOS / Android App
├── admin/      Vue 3 + Element Plus：平台运营后台（电脑浏览器用）
├── docs/       接口约定（api-v2.md、api-v3.md）、工作记录（worklog.md）
├── scripts/    前端路由核对、演示数据
└── AGENTS.md   协作开发说明（Codex / Claude 接手先读）
```

## 功能清单

| 模块 | 内容 |
| --- | --- |
| 找店 | 附近的店（营业中优先、按距离），分类筛选，能否送到一眼看清；首页轮播图、附近凑单 |
| 搜索 | 像淘宝一样**平铺所有结果**（每家店的每个商品一条），综合 / 离我近 / 价格 / 销量排序，按送货上门 / 自提 / 快递筛选，往下翻页；关键词、同义词（苞米 = 玉米）、**拼音全拼 / 首字母**；**精准找货**（扫条码、输登记证号、拍包装认出具体一款）时才出现**同款比价**；列表和商品页上「N 家有同款」可进比价；搜不到可一键发「求购」 |
| 店铺 | 店铺页、公告、营业时间、评分和评价、正在凑单；店铺海报 / 小程序码，可转发 |
| 上架 | 拍照 + 填价即发布；每个商品可选「本地配送」「快递发货」；**拍包装或扫条码认出具体是哪一款**（条码，或登记证号 + 规格），弹出「是不是这个？」点一下确认；商品库里没有的自动建档、运营核实；库存 |
| 下单 | 送货上门 / 到店自提 / 快递；在线支付 / 货到付款；结算页自动判断哪种可用及原因；再来一单 |
| 凑单 | 商家设凑单价、目标件数、天数、每人限购；分享链接拉人；凑够自动成团，没凑够老板 24 小时内选「照样发货」或「全部退款」（不选自动退款）；买家成团前可退出 |
| 接单 | 新订单**语音电话 + 短信 + 微信订阅消息**提醒老板，10 分钟没接再打一次；接单、拒单、送货、送达、收款、发快递；按村分组的送货清单 |
| 评价 | 完成后评分 + 文字 + 图片，商家可回复，店铺评分自动更新 |
| 求购 | 农户发「我要买 XX」，附近商家看到后报价，农户收到通知 |
| 资金 | 微信支付**电商收付通**：商家在小程序里填身份证和银行卡开通收款账户，买家付款进商家自己的账户，确认收货后自动解冻，商家自己提现（平台不碰钱，不是"二清"） |
| 商家工具 | 经营数据（本月单量、金额、热销）、证照管理（农药经营许可证等）、**赊账本**（记谁欠多少、还了多少） |
| 自动处理 | 15 分钟未付款取消；30 分钟未接单取消并退款；送达 24 小时 / 快递 10 天自动确认收货；凑单到期结算 |
| 内容安全 | 店名、商品名、评价、求购走微信内容安全接口，违规文字拦截 |
| 运营后台 | 数据看板（含"搜不到的词"）、店铺审核 / 停用、证照审核、商品下架、商品库（具体一款：品牌、规格、登记证号、条码；核实、合并重复）、商品归一、搜索同义词、分类、订单查询与仲裁取消、凑单、结算 / 提现 / 退款、评价、求购、用户、开通区域、轮播图、通知记录、管理员和操作日志 |

## 本地运行

### 1. 后端

需要 JDK 17+、Maven、MySQL 8。

```bash
mysql -uroot -p -e "CREATE DATABASE liangmanman DEFAULT CHARACTER SET utf8mb4"
cd backend
# 首次启动加 DB_INIT=always 自动建表并写入分类和常用品；之后去掉
DB_PASSWORD=你的密码 DB_INIT=always mvn spring-boot:run
```

默认端口 8080，`dev` 配置：模拟登录、模拟支付（开户立即成功）、模拟短信电话（只写通知记录）、模拟识别，店铺免审核。

开发环境运营后台账号：`admin` / `admin123`（首次启动自动创建）。

测试（不需要 MySQL）：`mvn test`

**升级已有数据库**：从第一批升级依次执行 `migration-v2.sql`、`migration-v3.sql`；从第二批升级只执行 `migration-v3.sql`（都在 `backend/src/main/resources/db/`），不要再用 `DB_INIT=always`。

### 2. 小程序

```bash
cd miniapp
npm install
npm run dev:mp-weixin
```

用**微信开发者工具**导入 `miniapp/dist/dev/mp-weixin`，勾选「不校验合法域名」。真机预览把 `src/config.js` 的 `BASE_URL` 改成电脑局域网 IP。

试用：「我的 → 我是农资店老板」开店发商品 → 换账号（开发者工具清缓存）→ 首页找到店下单 → 回商家账号接单送货。

### 3. 运营后台

```bash
cd admin
npm install
npm run dev     # 打开 http://localhost:5174/admin/
```

部署方式和 nginx 配置见 `admin/README.md`（后台放在同一域名的 `/admin/` 下，接口走 `/api/`）。

### 4. iOS / Android App

同一套 `miniapp` 代码用 HBuilderX 打包：HBuilderX 打开 `miniapp` → 发行 → 原生 App-云打包，需要在 DCloud 开发者中心申请 App 并填 `manifest.json` 的 `appid`。App 里的在线支付要另开**微信 App 支付**（同一个服务商可用），上架应用商店需要软著和 ICP 备案；建议小程序跑通后再做。

## 「同一款」怎么判断

各店卖的东西只有挂到商品库里的同一款，才算同款、才进比价。判断依据只看包装上能唯一区分一款货的信息：

- **条码相同** → 同一款；
- **登记证号 + 规格都相同** → 同一款（同一个登记证号的 40kg 和 50kg 是两款）；
- 只有名字像（都叫「复合肥 15-15-15」）不算同款，搜索里照常平铺，但不比价。

老板上架时拍包装或扫条码，系统认出是哪一款让他确认；商品库里还没有就自动建一条「待核实」，运营在后台「商品库」核实或合并。
